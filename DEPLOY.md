# Как поставить бота на сервер (VPS)

Инструкция «с нуля»: какой сервер купить, как подключиться, как залить бота,
как сделать автозапуск и бэкап. Всё проверено на Ubuntu 24.04.

Бот работает через **long polling** — он сам стучится в Telegram.
Поэтому **не нужны** ни белый IP, ни открытые порты, ни домен: достаточно самого
дешёвого VPS. Единственное требование — исходящий HTTPS до `api.telegram.org`.

---

## 1. Нужен ли сервер

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Свой компьютер** (`run.bat`) | бесплатно, уже работает | бот живёт, только пока ПК включён и не спит |
| **VPS за ~200–400 ₽/мес** | 24/7, не зависит от твоего ПК, свой IP | надо один раз настроить |
| **Бесплатный Oracle Cloud** | 0 ₽ навсегда | сложная регистрация, нужна карта, бывают отзывы ресурсов |

Если бот должен принимать заявки ночью и когда компьютер выключен — нужен VPS.

> ⚠️ **Виртуальный хостинг (shared) не подойдёт**, даже если там «есть Python».
> «Хост Лайт», «Хостинг-1» и подобные тарифы рассчитаны на сайты: там нельзя держать
> постоянный процесс 24/7 (его убивают по лимиту CPU), нет своего root и systemd.
> Боту нужен именно **VPS/VDS**: своя ОС, `systemctl`, процесс живёт постоянно.
> Наличие MySQL/Perl/CMS при этом не важно — боту они не нужны вообще.

---

## 2. Что покупать

Боту хватает минимума, он почти не ест ресурсы:

| Параметр | Значение |
|---|---|
| ОС | **Ubuntu 24.04 LTS** (или Debian 12) |
| CPU | 1 ядро |
| RAM | **512 МБ – 1 ГБ** |
| Диск | 10–15 ГБ SSD |
| Трафик | любой, бот тратит мегабайты |

Ориентир по цене — **150–400 ₽/мес**. Конкретные цифры у всех меняются,
смотри актуальные на сайте провайдера.

**Где брать с оплатой российской картой / СБП:**

- [Timeweb Cloud](https://timeweb.cloud/) — удобная панель, много дешёвых тарифов.
- [Beget](https://beget.com/ru/vps) — VPS рядом с их хостингом, есть оплата картой.
- [reg.ru](https://www.reg.ru/vps/) — старый крупный регистратор.
- [VDSina](https://vdsina.com/) — простые VPS без лишнего.
- Сравнение тарифов: [обзор недорогих VPS на vc.ru](https://vc.ru/services/2641599-nedorogie-vps-hostingi-2025).

**Зарубежные** (нужна иностранная карта, зато часто дешевле за те же ресурсы):
Hetzner (~€4.5), Contabo, Vultr, DigitalOcean.

> Важно: бери **Linux-тариф без панели управления** (без ISPmanager и т.п.) —
> панель не нужна и часто стоит дороже самого сервера. И выбирай локацию
> **Россия/Европа** — задержка до Telegram будет меньше.

> Есть вариант за 0 ₽ — бесплатный тариф Google Cloud. Он рабочий, но с оговорками
> (нужна карта, только три региона США). Подробно — в разделе 14 ниже.

## 3. Создание сервера

1. Зарегистрируйся у провайдера и пополни баланс.
2. «Создать сервер» → **Ubuntu 24.04** → тариф 1 vCPU / 1 ГБ.
3. При создании попросят **SSH-ключ** или дадут **пароль root**.

   - Проще: выбери «пароль» — придёт на почту.
   - Надёжнее: SSH-ключ. На Windows он делается так:
     ```powershell
     ssh-keygen -t ed25519 -C "werxlq-bot"
     # Enter, Enter, Enter — ключ появится в C:\Users\<ты>\.ssh\id_ed25519.pub
     type $env:USERPROFILE\.ssh\id_ed25519.pub
     ```
     Публичный ключ (одна строка `ssh-ed25519 ...`) вставляется на сайте провайдера.
4. Запиши **IP-адрес** сервера.

---

## 4. Подключение с Windows

Открой **Windows Terminal** или **PowerShell**:

```powershell
ssh root@IP_СЕРВЕРА
```

Первый раз спросит `yes/no` — пиши `yes`. Дальше либо попросит пароль,
либо пустит по ключу.

---

## 5. Первичная настройка сервера

Выполни по порядку (можно копировать блоками):

```bash
# обновление системы
apt update && apt upgrade -y

# нужные пакеты
apt install -y python3 git nano ufw fail2ban

# проверка Python (нужен 3.9+, в Ubuntu 24.04 — 3.12)
python3 --version
```

Необязательно, но полезно — отдельный пользователь для бота:

```bash
adduser --system --shell /usr/sbin/nologin --home /opt/werxlq-bot werxlq
```

## 6. Загрузка бота

### Самый простой путь — один файл

На своём компьютере открой папку `werxlq-bot` и выполни:

```powershell
deploy\deploy.bat IP_СЕРВЕРА
```

Скрипт сам:

1. зальёт папку на сервер в `/opt/werxlq-bot`;
2. запустит `deploy/install.sh` (Python, пользователь, права, systemd);
3. покажет статус сервиса и последние строки лога.

Пароль ssh он спросит по ходу. Если SSH на нестандартном порту — добавь его вторым
аргументом: `deploy\deploy.bat 203.0.113.10 2222`.

Проверить, что будет сделано, ничего не отправляя:

```powershell
deploy\deploy.bat 203.0.113.10 --dry
```

> Если Windows пишет «выполнение сценариев отключено» — запускай именно `deploy.bat`
> (он вызывает PowerShell с `-ExecutionPolicy Bypass`), а не `.ps1` напрямую.

### Вручную: scp

Открой PowerShell **на своём ПК** (не на сервере) и выполни из папки, где лежит `werxlq-bot`:

```powershell
scp -r .\werxlq-bot root@IP_СЕРВЕРА:/opt/
```

Папка окажется в `/opt/werxlq-bot`. Можно также залить через WinSCP/FileZilla —
они удобны, если хочется перетаскивать файлы мышкой.

### Вручную: git

Если проект лежит в репозитории:

```bash
git clone https://github.com/ТЫ/werxlq-bot.git /opt/werxlq-bot
```

## 7. Установка на сервере

Если шёл через `deploy.bat`, этот шаг уже выполнен. Иначе — на сервере:

```bash
cd /opt/werxlq-bot
sudo bash deploy/install.sh
```

Скрипт:

- проверит Python;
- создаст системного пользователя `werxlq`;
- скопирует бота в `/opt/werxlq-bot` (если запускаешь из другой папки);
- поставит права `600` на `.env`;
- установит и запустит systemd-сервис `werxlq-bot`.

Если `.env` не было — скрипт создаст его из шаблона и попросит вписать токен:

```bash
nano /opt/werxlq-bot/.env     # вставь TELEGRAM_BOT_TOKEN, сохрани: Ctrl+O, Enter, Ctrl+X
sudo bash deploy/install.sh   # запусти ещё раз
```

## 8. Проверка

```bash
systemctl status werxlq-bot        # должно быть active (running)
journalctl -u werxlq-bot -f        # живые логи, выход — Ctrl+C
```

В логах должно быть:

```
Бот запущен. Операторы: @werxlq, @Luotx
Реквизиты: 0000 0000 0000 0000 · Сбер · Имя Фамилия
```

Дальше открой бота в Telegram, нажми `/start` — он должен ответить.

Полезные команды:

```bash
systemctl restart werxlq-bot   # перезапуск
systemctl stop werxlq-bot      # остановить
systemctl disable werxlq-bot   # убрать из автозапуска
journalctl -u werxlq-bot -n 100 --no-pager   # последние 100 строк лога
```

---

## 9. Обновление бота

Когда поправишь тексты или логику у себя на ПК — залей папку заново и перезапусти:

```powershell
# на своём ПК
scp -r .\werxlq-bot root@IP_СЕРВЕРА:/opt/
```

```bash
# на сервере
sudo systemctl restart werxlq-bot
```

Данные заявок лежат в `/opt/werxlq-bot/data/state.json` и при копировании
не удаляются, если не удалять папку `data`.

---

## 10. Бэкап заявок

`data/state.json` — вся история заявок и список операторов. Настрой ежедневную копию:

```bash
sudo crontab -e
```

Добавь строку:

```
0 4 * * * /opt/werxlq-bot/deploy/backup.sh
```

Скрипт складывает копии в `/opt/werxlq-bot/backups` и удаляет старше 14 дней.
Забрать копию к себе:

```powershell
scp root@IP_СЕРВЕРА:/opt/werxlq-bot/backups/state-*.json .
```

## 11. Безопасность (5 минут, но важно)

```bash
# файрвол: всё входящее закрыто, исходящее разрешено
ufw allow ssh
ufw --force enable
ufw status

# защита от перебора паролей SSH
systemctl enable --now fail2ban
fail2ban-client status sshd

# автообновления безопасности
apt install -y unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades
```

Ещё:

- **токен бота** лежит в `/opt/werxlq-bot/.env` с правами `600` — не выкладывай его в чаты;
- если токен утёк — [@BotFather](https://t.me/BotFather) → `/revoke` → новый токен в `.env` → `systemctl restart`;
- пароль root лучше заменить на SSH-ключ: `ssh-copy-id`, затем в `/etc/ssh/sshd_config`
  поставить `PasswordAuthentication no` и `systemctl restart ssh`.

> ⚠️ **На Google Cloud и Oracle Cloud не включай `ufw`.** Там своя система firewall
> (правила в веб-консоли + iptables), и `ufw` может выбить тебе доступ по SSH.
> На таких серверах просто оставь правила провайдера по умолчанию.

## 12. Если Telegram не открывается с сервера

Проверка:

```bash
cd /opt/werxlq-bot
sudo -u werxlq python3 bot.py --net
```

Скрипт покажет, где рвётся: DNS, порт 443 или сам API.

Если порт 443 недоступен — нужен прокси. Впиши в `/opt/werxlq-bot/.env`:

```ini
TELEGRAM_PROXY=http://127.0.0.1:8080
```

и перезапусти сервис. Прокси-клиент (например, 3x-ui / xray / shadowsocks) ставится
на тот же сервер или рядом.

## 14. Вариант: Google Cloud Free Tier (0 ₽, но с условиями)

Google даёт **одну** вечно бесплатную виртуалку — для этого бота её хватает с запасом.

**Что входит** ([официальные условия](https://cloud.google.com/free/docs/free-cloud-features)):

| Ресурс | Бесплатно |
|---|---|
| VM | 1 × `e2-micro` (1 ГБ RAM), только `us-west1`, `us-central1`, `us-east1` |
| Диск | 30 ГБ **standard** persistent disk |
| Трафик | 1 ГБ исходящего в месяц (Северная Америка) |
| Бонус новым аккаунтам | $300 на 90 дней |

**Подводные камни — прочитай до регистрации:**

1. **Нужна банковская карта** для верификации (спишут ~$1 и вернут).
   Российские карты Google, как правило, **не принимает** — если карта не привяжется,
   вариант отпадает, и проще взять VPS за 200 ₽.
2. **Внешний IPv4** может тарифицироваться отдельно. Сразу поставь оповещение:
   Billing → Budgets & alerts → бюджет на **$1**.
3. Бесплатны только **`e2-micro`**, только **standard-диск** и только три региона США.
   Выберешь `e2-small` или SSD — придёт счёт.
4. Вторая VM, забытый диск, статический IP — тоже счёт. Раз в месяц заглядывай в Billing.
5. Пинг до Telegram из США ~100–150 мс — боту это не мешает.

**Пошагово:**

1. [cloud.google.com/free](https://cloud.google.com/free) → **Start free**
   (Google-аккаунт, карта, подтверждение телефона).
2. Создай проект, например `werxlq-bot`.
3. **Compute Engine** → **VM instances** → **Create instance**.
4. Настройки:
   - Name: `werxlq-bot`
   - Region: `us-central1 (Iowa)`, Zone: `us-central1-a`
   - Machine type: **e2-micro** (обязательно!)
   - Boot disk → **Change** → Ubuntu **24.04 LTS**, **30 GB**, **Standard persistent disk**
   - Firewall: галочки HTTP/HTTPS **не** нужны
5. **Create** → через минуту в списке появится **External IP** — это адрес сервера.
6. Вход:
   - **Проще:** кнопка **SSH** напротив VM — терминал прямо в браузере.
   - **Удобнее для скрипта:** добавить свой ключ:
     ```powershell
     ssh-keygen -t ed25519 -C "werxlq"     # Enter, Enter, Enter
     type $env:USERPROFILE\.ssh\id_ed25519.pub
     ```
     Console → **Compute Engine** → **Metadata** → вкладка **SSH keys** → **Add SSH key** →
     вставить строку `ssh-ed25519 ...` целиком → Save. Имя пользователя — то, что в конце
     ключа (`werxlq`).
7. Залить и поставить бота (на своём ПК, из папки проекта):
   ```powershell
   deploy\deploy.bat IP_СЕРВЕРА 22 werxlq
   ```
   Скрипт зальёт файлы в домашний каталог и установит сервис через `sudo`.
8. Проверить:
   ```bash
   systemctl is-active werxlq-bot
   sudo journalctl -u werxlq-bot -n 30 --no-pager
   ```

**Совсем без ключей** — SSH в браузере, загрузить архив проекта (в меню окна SSH есть
«Upload file»), распаковать и поставить:

```bash
sudo apt update && sudo apt install -y unzip
unzip werxlq-bot.zip -d ~/
cd ~/werxlq-bot && sudo bash deploy/install.sh
```

> На GCP **не включай `ufw`** — там свои правила firewall, и ufw легко отрежет SSH.
> Достаточно правил по умолчанию.

**Oracle Cloud** — похожая история: вечно бесплатный ARM-инстанс (до 4 ядер / 24 ГБ),
но регистрация с картой и частые отказы в верификации. Если карта проходит — ресурсов
там даже с избытком.
